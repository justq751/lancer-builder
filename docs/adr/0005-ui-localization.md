# Локализация интерфейса: два языка, ui.json, t()

Тексты интерфейса не живут в коде: канонический английский — в
`data/ui.json`, перевод — в `locales/ru/ui.json` (пары `{en, ru}`, как у
данных, ADR 0004). На экран они попадают через `t(key, params)` (HTML,
параметры экранируются) и `tText(key, params)` (простой текст для
`textContent`, `title`, списков, которые экранируют сами). Параметр с
именем `…Html` вставляется как разметка — его собирает и экранирует
вызывающий код. Множественное число — объект форм, выбор через
`Intl.PluralRules`. Подробности — в
`docs/superpowers/specs/2026-10-15-ui-localization-design.md`.

**Два независимых языка:** интерфейса (`lancer_ui_lang`) и данных
(`lancer_lang`). Режим «русский интерфейс + английские данные» — сверка с
книгой правил, принцип 5 `PRODUCT.md`. При первом заходе оба языка берутся
из браузера (`ru…` → русский, иначе английский); у тех, кто заходил до
этапа 4, интерфейс остаётся русским.

**Игровой термин** берётся из словаря данных (`stat_labels`, `enums`,
`glossary`) — по языку данных, если такой словарь есть; иначе (сокращения,
подписи интерфейса) — из `ui.json`, по языку интерфейса.

**Рассмотрено и отклонено:**
- один переключатель на всё — терял режим сверки;
- два плоских файла `locales/en/ui.json` + `locales/ru/ui.json` — перевод
  без оригинала рядом, расходится с форматом данных;
- английский текст как ключ (`t("Reset build")`) — любая правка английского
  ломает перевод.

**Последствия:**
- в `js/` и `index.html` (кроме `<head>` и комментариев) нет кириллицы —
  это проверяет `tests/unit/no-cyrillic.test.mjs`;
- ключи в коде — литералы; вычисляемый ключ объявляется комментарием
  `// i18n-dynamic: a.b, a.c` (сверка `tests/unit/ui-keys.test.mjs`);
- локальная переменная не может называться `t` — она скрыла бы `t()`;
- `<head>` хранит русские `<title>` и описание для поисковиков и превью
  ссылок, во время работы они переводятся атрибутами `data-i18n`.
