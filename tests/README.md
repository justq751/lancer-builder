# Тесты

Два слоя. **Юнит-тесты** (`tests/unit/`, `node --test`, без браузера)
проверяют чистую логику из `js/core/`. **Браузерные тесты** на Playwright
фиксируют, как приложение работает целиком, чтобы рефакторинг ничего не
сломал незаметно. Сайту по-прежнему не нужна сборка — npm здесь только для
запуска тестов.

## Запуск

```bash
npm install                       # один раз
npx playwright install chromium   # один раз, ~115 МБ
npm test                          # JSON + юнит (~0,2 с) + браузер (~25 с)
npm run test:json                 # только проверка, что все data/ и locales/ — валидный JSON
npm run test:unit                 # только js/core/, без браузера
npx playwright test smoke         # один браузерный файл
npx playwright test --ui          # интерактивно, с просмотром шагов
npx playwright show-trace test-results/<тест>/trace.zip   # разбор падения
```

Сервер поднимается сам (`tests/serve.mjs`, порт 4173). Если он уже запущен
вручную (`npm run serve`), Playwright использует его.

## Что проверяется

| Файл | Что фиксирует |
|---|---|
| `unit/i18n.test.mjs` | `localizeData`: перевод текста, неизменность ключей логики, откат пустого `"ru"`, данные-источник не мутируются |
| `unit/build.test.mjs` | `applyBuildState` (зажим чисел, обрезка строк, отброс неизвестного с текстом), миграции, правила креплений |
| `unit/rules.test.mjs` | `derived()` на эталонной сборке, лицензии и разблокировка, CORE от ранга 3, порядок в окнах выбора |
| `unit/share.test.mjs` | Упаковка ссылки `?s=` туда-обратно, сжатый и несжатый формат, отказ на мусор |
| `data.spec.mjs` | Итоговый датасет `L` для ru и en совпадает с эталоном (`tests/golden/`); перевод не меняет ключи логики (`frame.name`, `mount`, `type`, `source`, `tags`…); пустой `"ru"` откатывается на английский |
| `derived.spec.mjs` | Производные характеристики (HP, SP, бюджеты) эталонной сборки, посчитанные вручную по правилам; рост лимитов с LL |
| `persistence.spec.mjs` | Автосохранение, миграции старых сохранений, отбрасывание неизвестных id, экспорт → сброс → импорт, ссылка `?s=`, смена языка |
| `smoke.spec.mjs` | Сборка меха кликами с нуля; все вкладки и лист рендерятся без ошибок в консоли; клавиатура в табах; Esc в модалке |
| `mobile.spec.mjs` | Телефон 390 px: контент сразу под шапкой, док внизу; ни одна вкладка не шире экрана; строка бюджета открывает HUD-шторку (подсказка стата поверх неё); меню «⋯» закрывается перед диалогом; док прячется при наборе; переходы по разделам листа без `#` в адресе |
| `visual.spec.mjs` | Скриншоты ключевых экранов на 390 / 768 / 1440 px |

Юнит-тесты грузят `js/core/*.js` в изолированный контекст Node (`unit/load.mjs`)
ровно так, как их грузит страница, — без `export` в рабочем коде. `L`, `M`,
`state` задаются как глобальные переменные контекста; `coreData()` даёт
реальные базовые данные.

Общие части браузерных тестов: `helpers.mjs` (`openApp()` — открыть приложение с заданной
сборкой в localStorage и собрать ошибки консоли), `fixtures/builds.mjs`
(эталонная, устаревшая и «битая» сборки), `golden.mjs` (сравнение больших
JSON с указанием конкретных путей).

## Когда тест упал «правильно»

- **Обновили перевод или данные** → упадёт `data.spec.mjs` со списком путей
  вида `$.skills[0:sk_assault].name: "…" → "…"`. Если изменения ожидаемые:
  `npm run test:update`, затем посмотрите `git diff tests/golden/`.
- **Намеренно поменяли внешний вид** → упадёт `visual.spec.mjs`. Отчёт
  покажет разницу картинок; затем `npm run test:update` и проверка новых PNG
  перед коммитом.

`npm run test:update` перезаписывает **все** эталоны (и JSON, и PNG) — не
запускайте его, чтобы «починить» тест, причину падения которого не поняли.

## Скриншоты зависят от ОС

Шрифты рендерятся по-разному в Windows и Linux, поэтому эталоны лежат в
`tests/__screenshots__/<platform>/`. Сейчас есть только `win32`, поэтому
CI (Linux) запускает браузерные тесты с `--ignore-snapshots`: скриншоты
там не сравниваются, всё остальное — да. Вёрстку проверяйте локально
через `npm test`.

## CI

`.github/workflows/deploy.yml` при push в `main` сначала запускает
`test:json` → `test:unit` → `playwright test --ignore-snapshots`, и только
если всё зелёное — публикует сайт на GitHub Pages. Упал — сайт остаётся
прежним, отчёт с трассировками лежит в Actions → запуск → Artifacts →
`playwright-report`. Cloudflare деплоит независимо и тесты не ждёт.

## Известные баги

Тесты с `test.fail(...)` описывают найденный, но ещё не исправленный баг:
они «проходят», пока баг есть. Когда баг исправлен, Playwright сообщит, что
тест неожиданно прошёл, — тогда удалите строку `test.fail(...)`.
