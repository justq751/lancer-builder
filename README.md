# LANCER // РЕЕСТР — локализация контента

Этот пакет — переработанная версия конструктора персонажа Lancer,
подготовленная для постепенного перевода игровых данных (шасси, оружие,
системы, таланты, навыки, снаряжение и т.д.) на русский язык.

## Что изменилось

Раньше весь датасет `lancer-data` (около 300 КБ JSON) был вклеен одной
строкой прямо в `<script>` внутри HTML-файла. Редактировать или
переводить что-либо в таком виде было практически невозможно.

Теперь:

```
lancer-registry/
├── index.html                  ← сам сайт (разметка, CSS, логика)
├── data/
│   └── lancer-data.json        ← канонические данные (оригинал, EN)
├── locales/
│   └── ru/
│       ├── enums.json          ← общий словарь терминов (типы креплений,
│       │                          оружия, теги, роли меха, урон и т.д.)
│       ├── frames.json         ← перевод текста по шасси
│       ├── weapons.json        ← перевод текста по оружию
│       ├── systems.json        ← перевод текста по системам
│       ├── talents.json        ← перевод текста по талантам
│       ├── skills.json         ← перевод навыков (уже переведено полностью, как образец)
│       ├── core_bonuses.json   ← перевод CORE-бонусов
│       ├── pilot_gear.json     ← перевод снаряжения пилота
│       ├── backgrounds.json    ← перевод происхождений
│       └── manufacturers.json  ← перевод описаний производителей
└── tools/
    └── extract_locale_template.py  ← пересобирает шаблоны locales/*
```

Каждый файл — это отдельный, компактный JSON, который можно спокойно
открыть, отредактировать и закоммитить по одному, без риска сломать
остальной сайт.

## Как это работает во время загрузки

1. `index.html` при старте делает `fetch()` `data/lancer-data.json`
   (оригинальный английский текст + все игровые числа/теги/id).
2. Параллельно подгружаются файлы из `locales/ru/*.json`.
3. Скрипт "накладывает" перевод на английский текст: если для поля есть
   непустое значение `"ru"` — используется оно, если нет — остаётся
   английский оригинал. **Ничего не может "отсутствовать"**: сайт всегда
   рабочий, даже если переведена только часть контента.
4. Готовый объединённый объект превращается в привычный `L`/`M`, и вся
   остальная логика конструктора работает как раньше, без изменений.

Из-за такого подхода можно переводить материал сколько угодно частями —
хоть по одному оружию за раз — и сайт всё это время будет открываться
и работать корректно.

## ⚠️ Важно: почему часть значений НЕ переводится "в самих данных"

Некоторые поля используются не только для отображения, но и как ключи
игровой логики:

- **`frame.name`** — используется для отслеживания лицензий
  (`state.licenses[frame.name]`, сравнение `item.license === frame.name`).
  Если бы имя шасси переводилось прямо в данных, разблокировка оружия и
  систем по лицензии сломалась бы. Поэтому имена шасси (Everest,
  Blackbeard, Drake...) остаются как есть — это по сути имена
  собственные/названия продуктов, как и в большинстве других переводов
  Lancer.
- **`mount`, `type`, `source`, `tags`, `mechtype`** (например `"Main"`,
  `"Rifle"`, `"GMS"`, `"Reliable 2"`) — сравниваются в коде буквально
  (подбор креплений, фильтры, цвета источников). Эти значения тоже
  никогда не подменяются в самих данных.

Вместо этого такие "служебные" значения переводятся **только на
экране**, через функции `tr()` и `trTag()`, которые используют общий
словарь `locales/ru/enums.json`. Логика сайта продолжает сравнивать
исходные английские строки и поэтому не ломается — а пользователь видит
перевод.

Если однажды понадобится перевести и сами названия шасси "по-настоящему"
(с сохранением работы лицензий), нужно будет завести отдельное поле
вида `frame.display_name` и поправить ~10 мест отображения — это
осознанно не сделано сейчас, чтобы не рисковать поломкой билдера.

## Как переводить дальше

1. Откройте нужный файл, например `locales/ru/frames.json`.
2. Найдите нужный `id` (например `"mf_blackbeard"`).
3. Заполните пустые поля `"ru"` — рядом всегда лежит оригинальный `"en"`
   текст для сверки:

```json
"description": {
  "en": "The Blackbeard is IPS-N's aggressive solution to piracy...",
  "ru": "Ваш перевод здесь"
}
```

4. Для вложенных списков (`traits`, `ranks`) ключом служит английское
   название элемента — так переводы не разъезжаются, если у другого
   шасси/таланта поменяется порядок пунктов.
5. Сохраните файл — обновите страницу в браузере, изменения подхватятся
   сразу же (кэш браузера может требовать hard-reload).

Общие термины (крепления, типы оружия, теги, урон, роли мехов,
активации, названия производителей) переводятся один раз в
`locales/ru/enums.json` и автоматически применяются везде, где эти
слова встречаются в интерфейсе.

## Обновление данных из upstream lancer-data

Если вы получите новую версию `lancer-data` (новые шасси/оружие или
правки текста):

1. Замените `data/lancer-data.json` новой версией (тот же формат
   `window.LANCER`, просто сохранённый как отдельный JSON-файл, без
   `window.LANCER = ` и без завершающей `;`).
2. Запустите:

   ```bash
   python3 tools/extract_locale_template.py --lang ru
   ```

   Скрипт пересоберёт все файлы в `locales/ru/`, **сохранив уже
   сделанные переводы** и добавив пустые `"ru"` только для новых или
   изменившихся полей (у них будет пустая строка — значит, нужен
   перевод).
3. Переведите то, что появилось нового (`"ru": ""`).

## Запуск сайта локально

Открыть `index.html` напрямую через `file://` не получится — браузер
блокирует `fetch()` локальных файлов из соображений безопасности.
Нужно поднять любой простейший http-сервер в папке `lancer-registry`:

```bash
python3 -m http.server 8000
```

и открыть `http://localhost:8000/` в браузере. Точно так же сайт можно
выложить на любой статический хостинг (GitHub Pages, Netlify,
Cloudflare Pages и т.п.) — там `fetch()` работает без дополнительной
настройки.

## Переключатель языка

В верхней панели появилась кнопка **RU / EN** — она переключает язык
именно игрового контента (описания способностей, оружия, систем и
т.д.). Управляющие надписи интерфейса ("НАВЫКИ", "ШАССИ" и т.п.) и так
были на русском изначально и не затрагиваются этим переключателем —
если понадобится когда-нибудь и их сделать переключаемыми, для этого
нужен отдельный слой (сейчас они прописаны в HTML/JS напрямую).

## Дополнительные контент-паки (osr-data, wallflower-data)

В сайт также подключены два официальных дополнительных набора данных
Massif Press:

- **osr-data** — Operation Solstice Rain (шасси «Чомолунгма», новые
  таланты, экзотическое снаряжение);
- **wallflower-data** — No Room for a Wallflower, Act 1 (шасси «Кидд»,
  «Сагарматха», варианты «Энкиду»/«Чингисхан Mk I»/«Ласточкин хвост»,
  талант «Эмпат», экзотическое снаряжение).

```
data/packs/
├── osr-data.json         ← нормализованные данные пакета
└── wallflower-data.json
tools/
└── normalize_pack.py     ← конвертер схемы пакетов в формат сайта
```

Эти пакеты используют более новую схему `lancer-data` (например, теги
хранятся как `{"id":"tg_reliable","val":2}`, а часть текста способностей
лежит в отдельных массивах `actions`/`deployables`). `tools/normalize_pack.py`
приводит их к тому же плоскому виду, что и `data/lancer-data.json` —
превращая объекты тегов в обычные строки («Reliable 2») и подшивая текст
действий в поле `effect`/`*_effect` — так что existing-код отрисовки не
пришлось менять ни на строчку.

При загрузке сайт подтягивает `data/lancer-data.json` **и** оба файла из
`data/packs/`, объединяя их массивы (`frames`, `weapons`, `systems`,
`talents`, `pilot_gear`) в один список — новые шасси, оружие и таланты
из пакетов просто появляются рядом с базовыми в тех же вкладках.

Их перевод делается ровно так же, как обычно — новые id уже добавлены в
`locales/ru/*.json` (при следующем запуске `extract_locale_template.py`
они появляются автоматически, с сохранением уже сделанных переводов).

**Не поддержано:** категории `reserves.json` (резервы простоя) и
`environments.json` (окружения миссий) из обоих пакетов не подключены —
у самого сайта нет вкладки/интерфейса для них вообще (это не связано с
переводом, это отдельная нереализованная фича конструктора). Если
понадобится их когда-нибудь добавить, это отдельная задача по разработке
UI, а не по переводу.

Если выйдут новые версии этих пакетов (или другие LCP-паки), процесс
такой:

```bash
python3 tools/normalize_pack.py <lib_dir> data/packs/<name>.json "<label>"
python3 tools/extract_locale_template.py --lang ru
```

— первая команда конвертирует новый пакет, вторая добирает появившиеся
строки в файлы перевода.
