# LANCER — русский перевод контента

Модуль для Foundry VTT 13 и LANCER 3.1.3. Использует перевод из `locales/ru` проекта lancer-builder. Переводит названия и описания шасси, оружия, систем, модификаций, талантов, навыков, бонусов ядра, снаряжения пилота, состояний и тегов. Core и восемь официальных дополнений сопоставляются по `system.lid` и типу документа.

## Установка

1. Распакуйте `lancer-ru-content.zip` в каталог `Data/modules`, чтобы файл оказался по пути `Data/modules/lancer-ru-content/module.json`.
2. Перезапустите сервер Foundry, если модуль добавлен впервые.
3. В тестовом мире LANCER включите **Babele** (2.9.1 или новее), **lib-wrapper**, **Russian Translation (ru-ru)** и этот модуль. Установите русский язык. Отдельный **lancer-ru-ui-patch** отключите: начиная с версии 0.1.2 его 42 перевода включены сюда и согласованы с терминологией lancer-builder.
4. Импортируйте нужные книги штатным LCP Manager. После создания новых справочников перезагрузите страницу.
5. Откройте справочники мира: мехи/оружие/системы (`world.mech-items`), пилотские предметы (`world.pilot-items`), состояния (`world.status-items`). Перетащите предмет на лист.

Для нового мира сначала импортируется обычный английский контент, затем модуль показывает перевод. Повторно импортировать книги только ради перевода не требуется. Модуль не содержит собственных compendium-баз и не заменяет LCP Manager.

## Границы перевода

- `ru-ru` отвечает за основной интерфейс. Этот модуль включает дополнительные подписи листов пилота, меха, NPC и развёртываемого объекта из бывшего `lancer-ru-ui-patch`, а также исправляет заголовки характеристик и статичные подписи листа шасси. Общие термины берутся из локалей lancer-builder; полного перевода всего интерфейса LANCER модуль не заменяет.
- Уже сохранённые предметы мира и предметы внутри персонажей автоматически не обновляются. Для них не выполняется массовая миграция.
- Копия, перетащенная из переведённого справочника, может сохранить русский текст. Отключение модуля не переводит такие копии обратно. Исходные базы справочников модуль не переписывает.
- Текст применяется только при совпадении с известным английским исходником. При сравнении учитываются эквивалентные `<br>`, `<br/>`, `<br />` и регистр слова REPAIRS в данных 3.1.3. Другие изменения текста не игнорируются. Изменённые тексты и неизвестный homebrew остаются как есть. Некоторые поля обновлённых LCP могут остаться английскими; числовые поля и ссылки не заменяются.
- Сайт складывает часть действий и развёртываемого снаряжения в описание родителя. В модуле это описание переведено целиком; отдельные вложенные действия и Actor развёртываемого снаряжения могут оставаться английскими, если для них нет отдельного перевода.
- Для Thermal Charge `on_hit` не имеет отдельного целевого поля в unpacker модификаций 3.1.3; перевод основного эффекта сохраняется. Подробности адаптации и исключений — `coverage.json`.
- NPC, bonds, reserves, журналы, произвольный текст биографии пилота и категории вне словаря сайта не переводятся.
- Теги переводятся в клиентском объекте Tag, а не в настройке мира; числовые значения и сериализация `lid/val` сохраняются.

## Единое название Exposed — 0.1.12

Exposed в lancer-builder — «Открыт» (`locales/ru/statuses.json`, `GLOSSARY.md`). В `ru-ru` подпись значка называется «Уязвимость»; контентный модуль переопределяет `lancer.statusIconsNames.exposed` значением из словаря сайта после загрузки языковых файлов (`i18nInit`), чтобы порядок модулей не менял термин. Ссылки в результатах перегрева, документы справочника и подпись значка используют «Открыт». Механика и идентификатор `exposed` не меняются.

После установки 0.1.12 перезагрузите страницу и проверьте подпись статуса в интерфейсе. Сохранённые ранее сообщения и документы с собственными именами не переименовываются.

## Результаты перегрева в чате — 0.1.11

Добавлен перевод всех четырёх заголовков и шести описаний таблицы перегрева в `lang/ru.json`, включая варианты результата «Расплавление реактора» при разном остатке стресса. Встроенная кнопка проверки ENGINEERING на карточке перегрева отображается как «ИНЖЕНЕРИЯ»; её параметры и обработчики не меняются.

В исходной системе ссылки `@Compendium[world.status-items.Exposed]` / `Impaired` ищут статус по английскому имени, которого может уже не быть в переведённом индексе. Переведённые описания используют штатные ссылки LANCER `@LancerID[exposed]{Открыт}` / `@LancerID[impaired]{Ослаблен}`. Отображаемые имена берутся из локалей статусов сайта, поиск выполняет сама система по `system.lid`. Для открытия ссылки соответствующий документ статуса должен существовать в мире или доступном справочнике с индексированным LID; модуль не создаёт недостающие документы.

После установки 0.1.11 перезагрузите страницу и проверьте новый результат перегрева и открытие русского статуса по ссылке. Ранее сохранённые сообщения содержат старые тексты и ссылки и автоматически не переписываются. Броски, стресс, тепло и автоматическое применение состояний не изменены.

## Высота окна стабилизации — 0.1.10

После перевода окно стабилизации повторно подбирает высоту через штатный `setPosition({height: "auto"})`: русские подписи могут переноситься на большее число строк, чем английские, а первоначальная высота рассчитывается до перевода. Высота определяется содержимым и ограничениями экрана Foundry; другие диалоги не изменяются. На обычном экране все варианты и кнопки помещаются без прокрутки. При недостаточной высоте экрана прокрутка остаётся доступной.

Браузерный тест воспроизводит прежнее переполнение окна шириной 400 px и проверяет его отсутствие после перевода, сохраняя проверки выбора и кнопок. После установки 0.1.10 перезагрузите страницу и заново откройте стабилизацию; проверьте видимость последнего ряда действий и кнопок «Применить»/«Отмена».

## Окно стабилизации — 0.1.9

Переводятся заголовок, приглашение выбрать два действия, названия групп, шесть вариантов действий и кнопки применения/отмены. Название «Стабилизация» и «Перезарядка» берутся из локалей действий сайта. Обработчик `renderDialog` распознаёт окно по `.stabilize-wrapper`; прочие диалоги не изменяются. В заголовке заменяется только префикс `STABILIZE - `, имя меха сохраняется.

Значения `Cool`, `Repair`, `Reload`, `ClearBurn`, `ClearOwnCond`, `ClearOtherCond`, группы радиокнопок и штатные обработчики остаются прежними. Перевод результатов стабилизации в чате в эту версию не входит.

Проверка: `npx playwright test tests/foundry-stabilize.spec.mjs` (Windows: `npx.cmd`). После установки 0.1.9 перезагрузите страницу и откройте стабилизацию на тестовом мехе: проверьте подписи, выбор одного варианта в каждой группе, применение и отмену. Реальное изменение тепла, ОЗ, ремонтного запаса, загрузки оружия и состояний проверяется пользователем в Foundry.

## Крепления оружия на листе меха — 0.1.8

Переводятся названия штатных оружейных креплений, заголовки установленного оружия/систем и подсказки пустых оружейных слотов. Термины Main, Auxiliary, Heavy, Superheavy, Flex и Integrated берутся из `locales/ru/enums.json`. Обработчик применяется при отрисовке листа меха, включая повторную отрисовку после изменения снаряжения.

Изменяются только подписи заголовков и пустых слотов: типы креплений, служебные пути, правила установки оружия и кнопки сохраняются. Названия уже установленного оружия, пользовательские описания и неизвестные типы креплений не заменяются.

Проверка: `npx playwright test tests/foundry-loadout.spec.mjs` (Windows: `npx.cmd`). После установки 0.1.8 перезагрузите страницу и проверьте вкладку «Снаряжение»: Main/Aux, Flex, установку оружия в пустой слот, удаление/сброс крепления. Переимпортировать шасси или назначать мех заново не требуется.

## Исправление высоты характеристик меха — 0.1.7

У сетки характеристик LANCER 3.1.3 пять строк фиксированной высоты `5em`. Длинные переведённые названия HASE могут выстроить карточки в столбец, который выходит за границы сетки и перекрывается макросами. `styles/sheets.css` сохраняет минимальную высоту строк, позволяя им увеличиваться по содержимому. Правило ограничено сеткой листа меха; названия, значения и обработчики характеристик не меняются.

Вёрстка проверяется отдельно от Foundry: `npx playwright test tests/foundry-mech-layout.spec.mjs` (Windows: `npx.cmd`). Используется соответствующая часть разметки и правил LANCER 3.1.3; при ширине 900/1100 px и шрифте 14/18 px карточки HASE должны оставаться внутри сетки и выше макросов.

После установки 0.1.7 обновите страницу (при необходимости Ctrl+F5) и откройте лист меха. Проверьте всю карточку «Инженерия», значение и кнопку броска, а также отсутствие перекрытия с макросами при изменении размера окна.

## Перевод окна урона — 0.1.6

Переводятся базовый и дополнительный урон, настройки, типы урона, бронебойность, сверхурон, запрет снижения урона, половина урона, надёжность, результаты попадания и подсказки. В заголовке заменяется только служебное слово `DAMAGE` после названия оружия. Общий обработчик окон атаки и урона находится в `scripts/roll-hud.js`; словарь урона создаётся экспортёром из локалей сайта и специфичных фраз Foundry.

Текст вариантов типов урона переводится отдельно от их `value`: английские значения перечисления и формулы кубов сохраняются. Кнопки, флажки, обработчики событий и имена целей не заменяются. Браузерная проверка включает добавление новой строки урона, выбор типа и повторное обновление подсказок; окно атаки тоже проверяется.

После установки 0.1.6 перезагрузите страницу. Вручную проверьте окно урона без цели и с целью: добавление/удаление строк, выбор типов, ввод кубов, флажки, переключение попадания/промаха/критического попадания, «Бросок» и «Отмена». Проверьте итоговый бросок и применение урона в тестовом мире.

## Перевод окна броска атаки — 0.1.5

Переводятся модификатор, точность/сложность, флажки оружия и состояний, укрытия, итог, кнопки броска/отмены и их подсказки. Общие термины берутся из локалей сайта, специфичные подписи окна заданы в `build_ui()` экспортёра. Названия оружия и целей, числовые значения, флажки и расчёты не меняются.

Окно `AccDiffHUD` в LANCER 3.1.3 создаётся компонентом Svelte без событий отрисовки Foundry Application. `scripts/roll-hud.js` ожидает появления `#hudzone`, затем наблюдает только за этим контейнером и переводит известные строки внутри `form.accdiff` и `form.damage-hud`, в том числе после обновления целей и флажков. Обработчик включается при загрузке мира LANCER на русском языке; после смены языка нужна перезагрузка страницы.

Проверка браузерного обработчика отдельно от Foundry: `npx playwright test tests/foundry-hud.spec.mjs` (на Windows — `npx.cmd`). Проверяются создание и повторное открытие окна, обновления текста, сохранность элементов управления и отсутствие вмешательства при английском языке или другой системе.

После установки 0.1.5 перезагрузите страницу. Вручную проверьте бросок без выбранной цели и с целью: изменение модификатора, флажки, точность/сложность, подсказки, кнопки «Бросок» и «Отмена». При наличии состояний и укрытия проверьте их подписи и правильность итогового броска.

## Исправления 0.1.4

Исправлена подписка на отрисовку листов: Foundry 13 останавливает цепочку событий листа на `renderActorSheet` / `renderItemSheet` и не вызывает для них `renderApplication`. Поэтому обработка подписей встроенного меха в 0.1.3 не запускалась. Исправление также подключает перевод статичных подписей листа шасси к правильному событию. После установки 0.1.4 перезагрузите страницу и заново откройте лист пилота; для подписей характеристик заменять назначенного меха не требуется.

## Исправления 0.1.3

- Характеристики мехов на вкладке «Активный мех» листа пилота переводятся при отрисовке: система 3.1.3 выводит их напрямую, без ключей локализации. Обрабатываются только подписи внутри блока характеристик; имена мехов и значения не меняются. Перевод применяется только для LANCER на русском языке.
- Встроенный контент LANCER 3.1.3 называет особенность Эвереста `Replaceable parts`, а исходники сайта — `Replaceable Parts`. В `aliases.json` указан этот точный вариант имени; перевод теперь сопоставляет вложенные элементы также по известным английским вариантам. Произвольные изменения регистра и пользовательские описания не игнорируются.
- После установки перезагрузите страницу и откройте лист пилота. Если ранее сохранённый Эверест по-прежнему показывает английскую особенность, проверьте свежую копию шасси из переведённого справочника: существующие предметы персонажа автоматически не мигрируются. Не удаляйте настроенное шасси ради проверки — сначала используйте тестового меха.

## Обновление из репозитория

Из корня lancer-builder:

```text
npm run foundry:build
npm run test:foundry
```

На Windows при запрете PowerShell-скриптов используйте `npm.cmd`. Нужен Python 3.10+ и Node 24. Сборка не добавляет зависимостей. Архив создаётся в `foundry/releases/lancer-ru-content.zip`; готовые JSON и файлы `generated/` вручную не редактируются.

`lang/ru.json` и `generated/ui-labels.js` тоже создаются экспортёром. Соответствия ключей Foundry локалям `stat_labels`, `ui`, `enums`, `actions` и специфичные фразы Foundry находятся в `build_ui()` файла `tools/export_foundry_locale.py`. Пустой или устаревший перевод общего термина останавливает сборку. Короткие подписи берутся из интерфейсного словаря сайта, полные — из словаря характеристик; поэтому `hp` отображает «ОЗ», а `HP` — «ОЧКИ ЗДОРОВЬЯ».

При обновлении с 0.1.1 замените папку модуля, отключите отдельный патч и перезагрузите страницу. До ручной проверки держите старые файлы для возврата. Повторный импорт LCP и миграция персонажей не требуются.

`tools/export_foundry_locale.py --check` проверяет воспроизводимость экспорта. Английские варианты берутся из сохранённых upstream-снимков, русский текст — из существующих локалей; `coverage.json` перечисляет адаптации схемы и пропуски. При обновлении системы или книг требуется повторная проверка в тестовом мире.
